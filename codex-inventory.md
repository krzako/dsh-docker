# Inwentaryzacja forka Codexa przed integracją z DSH (N005)

Stan źródeł: `dockers/addons/codex/codex-rs`. To mapa ścieżek wymagających zachowania audytu i zmiany wykonawcy, nie deklaracja, że są już przejęte przez DSH.

| Ścieżka | Istniejący punkt kodu | Obowiązek integracji |
| --- | --- | --- |
| Zwykłe próbkowanie | `core/src/session/turn.rs`: `run_turn`, `run_sampling_request`, `try_run_sampling_request`, `build_prompt`; `core/src/client.rs`: `ModelClientSession::stream`. | Przechwycić złożony `Prompt` przed wysłaniem i wynik każdej próby, także częściowy/błędny. Tool specs pochodzą dziś z `step_context.tool_router.model_visible_specs()`. |
| Ponowienia | `core/src/responses_retry.rs`: `handle_response_stream_error`; wywołują go zwykłe próbkowanie i remote compaction v2. `core/src/client.rs` zawiera także odnowienie auth i własne ponowienie wywołania. | Korelować każdą próbę osobno i ustalić jednego właściciela retry z DSH, aby przerwanie/reconnect nie podwajały skutków. |
| Fallback transportu/modelu | `responses_retry.rs` przełącza WebSocket → HTTPS po budżecie retry; `client.rs` utrzymuje sesyjny stan fallback. `compact_remote_v2.rs` może ponowić compaction na poprzednim modelu. `session/mod.rs` ma politykę fallback modelu providera. | Traktować jako osobne model attempts z faktycznym provider/model/transport; żaden fallback nie może ominąć wykonawcy i audytu DSH. |
| Lokalna compaction | `core/src/compact.rs`: `run_inline_auto_compact_task`, `run_compact_task`, `drain_to_completed`, `replace_compacted_history`. Wysyła prompt przez `ModelClientSession::stream`; kod wprost wskazuje brak pełnego lokalnego rollout trace. | Zapisać prompt, odpowiedź, wejściową historię i faktycznie zainstalowaną historię zastępczą; obecny ślad nie wystarcza. |
| Zdalna compaction v2 | `core/src/compact_remote_v2.rs` i `compact_remote_v2_attempt.rs`: własny prompt, `run_remote_compaction_request_v2`, stream/retry, możliwy fallback modelu, `build_v2_compacted_history`. | Audytować obie próby i wynik checkpointu; nie polegać wyłącznie na zwykłych eventach turnu. |
| Kontekst i rollout | `core/src/context_manager`, `core/src/session/rollout_reconstruction.rs`, `core/src/session/mod.rs`: historia, rekonstruowanie, `replace_compacted_history`, utrzymanie dodatkowego kontekstu. | Snapshot do eksportu musi odzwierciedlać efektywną historię po compaction, nie tylko transcript UI lub surowe itemy. |
| Narzędzia | `core/src/session/turn.rs::built_tools`, `core/src/tools/spec_plan.rs`, `router.rs`, `parallel.rs`, `lifecycle.rs`, `handlers/`, osobny crate `codex-tools`. | Schematy i dispatch są dziś natywne; zastąpić je jednym dynamicznym katalogiem/wywołaniem DSH, blokując natywny dispatcher również przy błędnej konfiguracji. |
| Prompty zakładające native tools | `core/templates/model_instructions/`, `core/templates/agents/`, `core/templates/search_tool/`, `core/src/context/apps_instructions.rs`, `available_plugins_instructions.rs` oraz składanie bazowych instrukcji w `session/turn.rs`. | Przejrzeć i zmienić odniesienia do `apply_patch`, shell, MCP, web, delegacji i tool search; narzędzia DSH nie mogą być opisane jako niedostępne natywne narzędzia. |
| Inne binarki | `app-server`, `exec`, `cli` zależą od `codex-core`; `app-server` zależy też bezpośrednio od `codex-tools`. TUI również używa wspólnych protokołów/komponentów. | Fizyczne usuwanie narzędzi wymaga najpierw audytu zależności i zachowania kompilacji wymaganych binarek/protokołu app-servera. |

Szczególnie ryzykowne są ścieżki, które z zewnątrz wyglądają jak jeden turn, a wewnątrz wysyłają kilka żądań: retry, odnowienie auth, fallback transportu/modelu i compaction. N013–N015 oraz N029–N032 muszą objąć każde z nich, a testy N051 dowieść braku niezaudytowanego wyjścia do providera. Usunięcie samych nazw narzędzi z promptu nie blokuje ich wykonania; konieczna jest zmiana i test dispatchera.
