## N044 — odmowa wiernego importu archiwów log-only

Walidator ZIP po kontroli integralności zgłasza `DshArchiveManifestRequiredError` z kodem `DSH_ARCHIVE_MANIFEST_REQUIRED`, gdy archiwum nie ma manifestu przenośnego. Nie odtwarza kontekstu z transcriptu i nie wywołuje portów agentów. Nieprawidłowy manifest i niebezpieczny kontener zachowują swoje błędy walidacji. Poprawne archiwum przenośne bez prywatnego checkpointu nadal podlega zwykłej ocenie zgodności targetu. Dokumentacja opisuje wybraną, dozwoloną przez N044 odmowę; produktowy endpoint importu pozostaje w otwartych zadaniach.

Dowody: `zip-validation.host.spec.ts` i `archive.host.spec.ts` 94/94; `archive-bundle.host.spec.ts` 60/60 (w tym odmowa przed źródłem, capabilities, credentials i importem). Typowany lint czterech zmienionych plików przeszedł po zawinięciu komentarza. `doc-sync`: 30/31; jedyny brak JSDoc pola `code` poprawiony, ponowione `verify-export-jsdoc` przeszło. `git diff --check` bez błędów. Test endpointu używa rzeczywistych bajtów bieżącego eksportu log-only; pozostałe testy obejmują nazwy historycznych generacji logu oraz odróżnienie uszkodzonego manifestu i traversal.

## N277 — porównanie plików migawki

Zbiorczy preview zwraca porównania plików zweryfikowanej migawki z autoryzowanym workspace: nowe, identyczne, zmienione, konflikt typu lub rodzica. Strumieniowy odczyt porównuje SHA-256 i rozmiar. Dowiązania są konfliktami; wykryta zmiana pliku/katalogu podczas odczytu i błędy dostępu przerywają operację. Uchwyty zamykają się również przy anulowaniu. Brak migawki (null) różni się od pustej migawki ([]). Nie ma zapisów, aplikacji ani deklaracji zgodności całego workspace: pliki dodatkowe i metadane nie są porównywane. To obserwacja, nie rezerwacja przeciw równoległym zmianom ani sandbox systemu plików.

Dowody: workspace-preview 16/16, archive-bundle 61/61, w tym zbiorczy preview rzeczywistego ZIP i niezmienione lokalne pliki. Build typów pakietu i host tsc przeszły. Typowany lint źródeł i testów przeszedł po poprawkach formatowania. doc-sync 30/31; jedyny nieaktualny numer linii w config-catalog zregenerowany, gen-config-catalog --check przeszedł. git diff --check przeszedł. N226/N227 i fingerprint N037 pozostają otwarte.

## N278 — prywatny staging migawki

withDshWorkspaceSnapshot strumieniowo zapisuje pliki do świeżego prywatnego katalogu, tworzy je ekskluzywnie z uprawnieniami właściciela, sprawdza cały ZIP i zgodność z manifestem preview, a dopiero potem wywołuje konsumenta. Puste pliki i pusta migawka są obsługiwane. Staging i uchwyty są sprzątane po sukcesie, błędzie zapisu/walidacji/konsumenta i anulowaniu ekstrakcji. Po wejściu do konsumenta za anulowanie i punkt zatwierdzenia odpowiada jego transakcja. Docelowy workspace nie jest modyfikowany. V1 nie odtwarza praw dostępu ani pustych katalogów źródłowych; nie jest to jeszcze pełna transakcja importu.

Dowody: ZIP i archive-bundle 97/97 przed ostatnim testem granicy anulowania; finalny zakres staging 8/8 (29 pozostałych prób niepowtarzanych). Testy obejmują plik 2 MB, pusty plik/migawkę, zmianę manifestu i payloadu spoza migawki, konflikt ścieżek, limit, błąd konsumenta i anulowanie podczas dekompresji. Linux fixture sprawdza brak pozostawionych deskryptorów całego własnego katalogu, w tym usuniętego stagingu. Typy pakietu i hosta, typowany lint oraz git diff --check przeszły. doc-sync 31/31.

## N279 — spójne metadane załączników całego drzewa

Eksporter korzysta ze wspólnych map referencji podczas skanowania root i wszystkich potomków. Sprzeczne metadane są sprawdzane przed deduplikacją, tak samo jak w importerze. Usunięto scalanie map, które pozwalało potomkowi zastąpić metadane root bez kontroli. Zgodne referencje nadal współdzielą payload.

Dowody: archive.host 67/67, w tym konflikty obrazów i plików między sesjami dla log i portable oraz dotychczasowa zgodna deduplikacja. Build typów pakietu, host tsc, typowany lint i doc-sync 31/31 przeszły. Dalszy przegląd N036 wykazał brak końcowej kontroli zmian logów/drzewa podczas strumienia; dopisano niewykonane N280 przed implementacją.

## N280 i N036 — końcowa bariera spójności eksportu

Przed manifestem portable ZIP eksporter ponownie flushuje i odczytuje każdy wyeksportowany log, porównuje SHA-256 jego dokładnej serializacji oraz ponownie sprawdza zestaw potomków. Przechowuje digests, a nie wszystkie logi drzewa. Odczyty kontrolne zaczynają się po zebraniu logów i zakończeniu strumieni kontekstu/checkpointu. Zmiana lub brak logu, niepotwierdzony flush i zmiana drzewa przerywają strumień bez ukończonego ZIP. Nie jest to blokada przyszłych zmian po zweryfikowanym odczycie.

Dowody N280: archive.host 72/72, w tym zmiana root/potomka, zniknięcie potomka, nowy potomek, niepotwierdzony końcowy flush oraz kolejność odczyt → źródło → kontrola → konsumpcja → końcowy odczyt. Typowany lint, build typów pakietu, host tsc, doc-sync 31/31 i git diff --check przeszły. N036 zamknięto na podstawie tej bariery i istniejących przechodzących prób tego samego pliku: flush live root/potomków, odmowa bez durability listener, podwójny odczyt root wokół pobrania źródła, brakujące/zmienione bloby, luki/powtórzenia audytu, niezakończona compaction i walidacja wnętrza checkpointu V2. Zwykły format log pozostaje transcript-only; domyślny wybór portable i opcjonalny snapshot produktu nadal należą do N035/N037.

## N282 — wersjonowany fingerprint workspace

Portable ZIP zapisuje SHA-256 uporządkowanych rekordów względnych ścieżek, bajtów plików, pustych katalogów i treści dowiązań bez odczytywania ich celów. Preview porównuje tylko rozpoznany algorytm; stare digests bez oznaczenia pozostają niezweryfikowane. Niedostępność workspace jest jawna i nie blokuje eksportu rozmowy; wykryte zmiany podczas odczytu oraz anulowanie przerywają operację. Hashowanie wymaga odczytu całego drzewa i pamięci na metadane ścieżek, nie kopiuje workspace do ZIP. Zgodność zawartości nie potwierdza metadanych środowiska. N037 pozostaje otwarte.
